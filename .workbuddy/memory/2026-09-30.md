## APP 内集成蓝牙推送的可行性结论（2026-09-30）
- **Web Bluetooth 在 WebView 里永不可用**：WebView 即 Chromium，但 Google 明确不实现（官方 web.dev《Web on Android》：有 OS 级替代的 API 不进 WebView），无 flag 可开；嵌完整 Chromium（+50MB）不划算 → "换内核"路线否决
- **Custom Tabs 能用 Web BLE（真 Chrome 进程）但体验有硬伤**：Custom Tab 全屏盖在 APP 上，用户必须关掉它才能操作计分界面；关掉即页面销毁 → 自动推送中断。折衷：ACTION_VIEW 跳真 Chrome，用户切回 APP 后 Chrome 后台 tab 继续 WS+BLE 推送（需手机装 Chrome）
- **推荐正解 = 原生 BLE 桥（不依赖 Web Bluetooth）**：服务器本来就在 APP 进程内（RiichiServer），游戏状态广播时直接调原生 BLE 客户端推送；渲染走服务端 Canvas（与 COOIOT /display 方案同款）；tagpush.js 的 EPD-nRF5 协议用 Java 重写（BluetoothGatt 分块写 + 通知订阅，约 400-500 行）+ BLUETOOTH_SCAN/CONNECT 运行时权限（Android 12+，用户机 Android14 OK）。tag.html 保留作 Chrome 备用通道

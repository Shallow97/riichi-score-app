## 修复：逐局分数记录未反映立直扣的 1000 点（用户反馈）

### 现象与根因
用户报告：A 立直、B 放铳给 C 满贯，A 的逐局变化显示 `(0)`，应为 `(-1000)`。
三处显示同源：结算结果弹窗、对局界面「半庄分数记录」、历史详情「逐局分数记录」。

根因在 `rules.js` `buildHandRecord()`：`delta = 结算后分数 − 快照分数`
（`games`/`pts` 与快照的 `p.points` 之差），但该快照是 `applyRoundResult()` 一进门
（第 139 行 `pushSnapshot`）才拍的，此时 `doRiichi()` 早已扣走 1000 并入了供托池
→ 这笔落在快照「之前」，差值里没有它 → 立直者显示 `(0)`。
反方向的 `+供托` 落在快照「之后」，所以**已经**计入和牌者本局 delta（这部分本来就对）。

### 用户确认的口径
1. 立直 -1000 **计入立直那一局**；供托被收走时 +1000 记在**收走那一局**（沿用现有行为）。
   → 跨局相加仍守恒：各局 delta 之和 + 留在池中的供托 = 0。
2. 三处显示同步修改。
3. **只对新对局生效**（老对局 hand 记录无 `riichi` 字段 → 原样显示，不重算）。
4. 记录里给立直者加一个迷你立直棒小标记。

### 改动
- `js/rules.js` `buildHandRecord()`：从 `game.players`（须在 applyRoundResult 第 4 步
  「清空本局立直状态」**之前**读取）取 `p.riichi`，写 `players[].riichi` 并在 delta 中
  减去 `riichiPaid = 1000`。函数头注释记录了完整口径与调用时序约束。
- `js/app.js`：
  - 抽出共用 `handRecordHtml(rec)`（半庄分数记录 + 历史详情 逐局记录同一版式），
    立直者名字后插 `<span class="rl-player-riichi">`（迷你立直棒）。
  - 新增 `currentRiichiNames()`；`renderResultPlayers(transfers, riichiNames)`
    对名单内玩家额外 `-1000`。三处调用点（`finalizeSettlement` / 其他流局 / 荒牌流局）
    都在 `Rules.applyRoundResult` **之前**取好名单（结算后立直标记会被清空）。
- `css/style.css`：`.rl-player-riichi` / `.rl-player-riichi-dot`（14×5 白条+border-strong
  描边 + 3px 红点，浅色卡片上可见）。
- 测试：新增 `tests/riichi-delta-test.js`（47 断言）；更新
  `tests/multiron-honba-kyotaku-test.js`（旧断言按旧口径写死 P东=-3600/sum=1000，
  已改为 -4600/sum=0，其注释原本就写着旧口径不守恒）。

## 界面改版：工作量评估 + 视觉稿（未改代码）

用户提出「想重新设计界面 UI，工作量大吗」。**只做了评估与视觉稿，未动任何生产代码。**

### 改造三档的实际代价（实测数据）
| 档位 | 改动范围 | 波及测试 | 结论 |
|---|---|---|---|
| ① 换皮 | `style.css` 19 个色变量 + 48 处散落色值 | 0 | 轻 |
| ② 局部改版 | ①+`index.html` 391 个 class + `app.js` 52 行拼 HTML | 5~8 个文件（`domtest.js` 一家 434 处引用） | 中 |
| ③ 全面重做 | 全部 + 26 个弹窗交互链路 | 几乎全部 | 重 |

**关键结论：成本不在 CSS，在「结构被 ~1000 处测试断言锁死」。**
- CSS 底子好：`:root` 19 变量、128 处 `var()` 引用 → 换色调改 20 行即可。
- **全项目无 `@media`**（固定 WebView 窄屏 ~393px）→ 不必做响应式。
- ⚠️ **`view-lock-test.js` 是唯一读 `style.css` 的测试**：它正则断言
  `.modal-view .view-actions .btn` 规则体内含 `height:50px` 与 `display:flex`。
  重写 CSS 时若动这条规则，必须同步该测试。其余 20 个测试都不读 CSS。
- `design-preview/` 已有设计基线（设计总览 + 7 张关键界面图 + 立直棒 SVG）。

### 现状「看着旧」的 5 个具体成因（诊断结论）
1. `.btn { border-bottom: 4px solid }` 立体厚度按钮（iOS 6 时代拟物手法）——最大元凶
2. 深墨绿 `#1E7A4E` 一色承担全部角色（标题/按钮/数值/局数/边框）→ 无层次
3. `font-weight: 800` 滥用十几处（中文 800 会发糊发笨）
4. 圆角 8/10/12/14/16/18/20px 七种混用
5. 桌面用 `radial-gradient` + `inset` 内发光 + 4px 实边 → 显脏

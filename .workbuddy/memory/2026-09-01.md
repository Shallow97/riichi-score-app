## BUG修复：成员(手机)操作时房主(电脑)收不到状态同步
- 用户实测发现：电脑(房主)进行立直/和牌结算时，手机浏览器能实时同步；但反过来手机(成员)操作时，电脑无反应。
- 根因：serve.js 的 `broadcastState(state)` 只遍历 `room.members`，**漏发 `room.host`**。房主在 members 集合之外，所以当操作者是成员时，提交的 host-state 广播不到房主。`broadcastOperator` 是对的（host+members 都发），唯独状态广播漏了 host。
- 修复：`broadcastState(state, exceptWs)` 改为同时遍历 members 和 host，并跳过提交者自己（exceptWs），避免无意义回显/覆盖操作者正在进行的操作。`host-state` 分支调用 `broadcastState(msg.state, ws)`。
- 同步修复：android RiichiServer.java 的 host-state 分支同样漏发 host，改为对 members + host 广播（跳过提交者）。Java parity 测试同步更新其状态机。
- 关键行为变化：**操作者提交后不再收到自己的回显**（被 exceptWs 跳过），其他端（含房主、其他成员）收到。因此前端 app.js 的 onState 回调对操作者本人不触发，无 UI 覆盖风险；房主端注释"房主端不会触发此回调"仍成立（房主自己是提交者时被跳过）。
- 测试更新：net-integration 新增回归用例 testMemberToHostBroadcast（成员提交→房主收到 + 非操作者提交被忽略），增至13项；java-server-parity 用例1改为验证"成员(操作者)提交→房主收到"（原断言是成员收到自己回显，现语义反转）。
- 验证：全部测试 142 项通过（net-integration 13 / java-parity 9 / domtest 116 / net-test 4）。已重启运行中的服务器进程(PID 4128→12704)加载修复，并对运行中实例实测"成员→房主"同步 ✓。

## 【真正根因确认并修复】成员(手机)操作不同步到房主(电脑)
- 用 jsdom(只模拟成员端)+真实ws房主 端到端复现成功，定位到真正根因在【客户端 net.js】而非服务器。
- 根因：成员申请操作权成功(action-granted)后，服务器会立刻广播 operator-change。若成员【尚未设置名字】，服务器 broadcastOperator 发 operator-change name=null。旧版 net.js 的 operator-change 分支写死 `if (m.name===null) iAmOperator=false`，把"操作者无名"误判成"操作权已释放"，把刚拿到的 iAmOperator 重置为 false。于是成员立直/结算后 saveActive→broadcastOnSave 因 `!iAmOperator` 被静默丢弃，广播永远发不出去 → 房主收不到。
- 触发条件：成员没设名字。真实用户加入房间若不填名字即触发（多数失败），有名字则正常——这解释了为何之前 verify-full-chain(成员设了名字)通过、而用户实测失败。
- 修复(net.js)：operator-change 分支【不再】根据 name===null 清除 iAmOperator。iAmOperator 只由 action-granted(置true)、releaseAction/leaveRoom/host-left(置false) 管理。这样无论成员有无名字，申请操作权后都能正常广播。副作用安全：单房间互斥下操作者切换不依赖此清除；action-denied 分支仍置 false。
- 附带清理：requestAction 内 `Net.onOperator(onOp)` 在回调里重复注册自己，导致 operatorListeners 无限累积 → 移除内部那次注册。
- 测试：java-server-parity 新增"用例4 无名成员申请操作权并广播→房主收到"(3项断言：申请授予、申请后amOperator保持true、广播到房主)。全部测试145项通过(net-integration 13 + java-parity 12 + net-test 4 + domtest 116)。
- 已同步修复后的 net.js 到 android/app/src/main/assets/。已移除 serve.js 临时诊断日志并重启服务器(PID 1440)。
- 教训：①测试客户端务必覆盖"成员不设名字"场景(真实用户可能不填)；②广播依赖 iAmOperator 等客户端状态时，要仔细审视服务器 broadcast 的边界(无名)；③server/客户端都要修，不能只修服务器广播层。

## 【新增功能】房主结束对局 → 手机(成员)端同步结束并跳转历史页
- 需求：电脑端点"结束并保存"后，手机端应同步结束本次对局并跳转到对局历史界面，而不是卡在结束前一刻。

- 方案：新增一条广播消息类型 game-end（携带归档记录，线上以序列化字符串传输，兼容 Java 字符串协议）：
  - serve.js：host 发 {type:'game-end',record} → 广播给所有 members（仅房主可发）。
  - net.js：新增 Net.endGame(record)（房主用，record JSON.stringify 成串）与 Net.onGameEnd(cb)（成员用）；收到 game-end 时 JSON.parse 反序列化 record 后回调。
  - app.js：bindEnd 里归档后调用 Net.endGame(rec) 广播；成员端 onGameEnd 回调里 Storage.receiveFinished(record) 插入本机历史、game=null、clearActive、showPage('page-history')+renderHistory。
  - storage.js：archiveGame 改为返回归档记录；新增 receiveFinished(record)（按 id 去重插入本机历史）。
  - RiichiServer.java：新增 game-end case（与 serve.js 一致，仅房主→成员广播，record 走序列化字符串）。
- 关键设计决策：record 在线上以"序列化字符串"而非对象传输，与 host-state 的 state 一致，因 RiichiServer.java 的 jsonStr() 只能解析字符串值，无法处理嵌套对象。
- 测试：新增 net-integration 用例"房主结束→成员收到game-end"(+2)、java-server-parity 用例5"成员onGameEnd触发并携带一致记录"(+1)、新增 tests/game-end-app-test.js(端到端验证成员跳历史页+去重，+7)。全部测试 156 项通过(net-integration 15 + java-parity 14 + net-test 4 + domtest 116 + game-end-app 7)。

## 「和牌结算/立直」操作权平权互斥（根治双结算 + 关弹窗不释放）
- 背景两现象：①房主点开结算弹窗不走服务器互斥(旧 `tryBeginOperate`/`canOperateLocal` 对 host 恒放行、`Net.requestAction` 对 host 短路)，导致房主与持权成员同时开同一笔结算弹窗→双倍计分；②成员关掉结算弹窗(×/空白/取消)只 `closeModal` 不 `releaseAction`，操作权被一直占住，他人只能等其刷新。
- **结论**：房主端服务器 RiichiServer.java / serve.js **无需改动**——它们本就把 host 当普通可申请操作权的 ClientConn(能 request-action 成为 operator、能收 broadcastOperator)。核心改在前端 net.js + app.js。
- net.js：`iAmOperator` 初值由 `host` 改 `false`(房主不再天然持权)；room-created/host-left/onclose/leaveRoom 复位也改 false；`requestAction` 去掉 `host` 短路，联网时房主与成员统一向服务器申请(离线单机仍 host 本地授予)；`releaseAction` 去掉 `!host` 限制(房主持权也发 release-action)。
- app.js：`canOperateLocal`/`tryBeginOperate` 去掉房主恒 true/直接放行，联网全员走申请，被占则 toast "XX 正在操作"不开弹窗(平权互斥)。新增 `OP_MODALS` 集合(modal-riichi/settle-type/pay/recv/amount/more/tsumo/tsumo-amounts)+`closeModal` 微任务(setTimeout 0)钩子：若 amOperator 且无任何 OP 弹窗仍打开→`Net.releaseAction()`(根治现象2；利用微任务避开同一事件内 close+open 推进的误判)。结算完成/立直接算完成的显式 release 改为按 `Net.amOperator()`(不再 `!isHost`)。netHint 文案去掉"房主拥有全部操作权"，改全员平权措辞。
- **测试**：java-server-parity.js 新增用例5(host 申请被授予→amOperator=true→成员被拒→host 释放→成员可接手) 20/20；新增 operator-release-test.js(持权成员打开结算/立直弹窗→点×关闭自动 releaseAction) 9/9；全回归 domtest196/continue14/multiron24/game-end7/end-kyotaku-guard28/operator-release9/java-server-parity20 全绿。
- 已同步 app.js+net.js→android assets，assembleDebug 出 APK(sha256 c03cc92b...)，解包校验平权 marker 已打入，并安装到小米14 冒烟通过。

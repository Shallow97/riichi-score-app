## 修复 APK 一打开就闪退的问题

用户反馈安装打包好的 APK 后打开即闪退。排查 Java 源码、Manifest、build.gradle 后定位根因：

### 根因
`targetSdk 34`（Android 14）+ 前台服务使用 `foregroundServiceType="dataSync"`，但 Manifest **缺少 `android.permission.FOREGROUND_SERVICE_DATA_SYNC` 权限**。
Android 14 强制要求声明与 FGS 类型对应的细分权限，否则 `startForegroundService()`/`startForeground()` 抛 `SecurityException`，导致 `MainActivity.onCreate()` 崩溃 → 打开即闪退。

### 修复内容
1. **AndroidManifest.xml**：新增 `<uses-permission android:name="android.permission.FOREGROUND_SERVICE_DATA_SYNC" />`
2. **MainActivity.java**：
   - `startServerService()` 包 try-catch，前台服务启动失败不崩溃（服务退化为仅 WebView 端）
   - 新增 `requestNotificationPermission()`：Android 13+ 运行时请求 `POST_NOTIFICATIONS`（权限码 1001）
   - 新增 `onRequestPermissionsResult` 回调
3. **ServerService.java**：`startForeground()` 包 try-catch，避免个别机型启动失败崩溃

## 追加4：根因已定位并修复 —— readHttpRequest 致命 bug
不依赖用户日志，通过 Node 精确复现 `readHttpRequest` 逐字节逻辑，**直接复现出根因**：

### 根因
`RiichiServer.readHttpRequest()` 的 `ByteArrayOutputStream lineBuf` **从未写入任何字节**（缺 `lineBuf.write(c)`）。导致：
- 每读到 `\r\n`，`lineBuf` 都是空 → 每一行解析为空串
- 第一个空行就 `break` → `req.method` 和 `req.path` 都是 null
- `serveStatic(null)` 兜底返回 index.html

**连锁后果**：服务器对所有请求（HTML/CSS/JS/WebSocket）都返回 index.html 的内容：
- HTML 请求 → 返回 index.html → ✅ 用户能看到页面
- **CSS 请求 → 返回 HTML → WebView 不识别 → 无样式（白底黑字）**
- **JS 请求 → 返回 HTML → WebView 不执行 → 无法跳转**
- **WebSocket 握手 → 判断失败 → 成员端连不上**

这完美解释用户"HTML 正常但 CSS/JS 全部失效"的症状。之前所有测试通过是因为服务器总能兜底返回 index.html，掩盖了 bug。

### 修复
`readHttpRequest` 加字节写入逻辑：
- 读到 `\r\n` → 处理当前行并 `prev=-1` 复位
- else 分支：`if (c != '\r' && c != '\n') lineBuf.write(c)`，只写普通字节

### 验证（Node 复现）
- CSS 请求 → path=/css/style.css ✓
- WebSocket 握手 → ws=true，Sec-WebSocket-Key 正确解析 ✓
- 首页 host → isHost=true ✓
- 构建 SUCCESSFUL，新 APK 75,708 字节，签名有效

### 教训
- 服务器逻辑"看似正常"（兜底掩盖错误）时，要用真实字节流逐层复现测试，不能只验证文件存在
- `ByteArrayOutputStream` 写入是 HTTP 解析的基础，遗漏会导致所有请求被兜底路由

## 追加9：梳理房主首页"断开连接"按钮点击后的执行链路（用户咨询）
用户询问：房主 APP 首页下方"断开连接"(btn-leave-room) 按钮点击后执行什么。

### 前端链路（app.js:106-111）
1. `Net.leaveRoom()`(net.js:158)：若 ws.readyState===1 → `ws.send({type:'leave-room'})`；随后本地置 `connected=false; members=1; operator=null; iAmOperator=host(true)`，`emitStatus()` 触发状态监听。
2. `toast('已断开连接')`。
3. `updateNetStatusUI()`(app.js:115)：重渲染首页联网状态条。

### 关键非直觉点（排查后确认）
- **leaveRoom 不调用 ws.close()**，WebSocket 仍保持 open。
- **服务器端 handleMessage 的 switch 没有 "leave-room" 分支**（落在 default 被丢弃，什么都不做）。因此点击按钮只影响房主本机前端状态，服务器 room.host / members / state 均不受此消息影响。
- 房主 `host=true`(net.js:35) 由 URL `?host=1` 决定，点击后不改变 → 断开后 UI 会回到"单机/未连接服务器"态，但 WebSocket 其实仍连着服务器。
- updateNetStatusUI 中 `Net.isOnline()` 仍为 true（ws 没关），而 `isInRoom()=false` → 会走 app.js:125 的"未连接服务器（单机模式）"分支显示。

### 对局数据(room.state)在真正断开时
- 房主 socket 真正 close 才触发 onDisconnected(服务器端 167-181)：host 清空、广播 host-left、清 members/operator。但 room.state（对局数据）**不会被清空**，下次重连/成员加入仍沿用。
